# Двусторонние оценки функции Беллмана в двумерной задаче Фуллера

## О проекте

Рассматривается задача оптимального управления

```
min (1/2) ∫₀^∞ ‖x‖² dt,     ẋ = y,  ẏ = u,  u ∈ D = {‖u‖ ≤ 1},  x, y ∈ ℝ²
```

— двумерный аналог задачи Фуллера с особой траекторией второго порядка в начале
координат (Зеликин–Борисов, гл. 7.2). Полный оптимальный синтез для неё
неизвестен: аналитически найдены только коллинеарные траектории (сводятся к
одномерной задаче Фуллера) и однопараметрическое семейство самоподобных решений.

Проект строит **двусторонние оценки функции Беллмана**, сравнивает методы между
собой и проверяет их на состояниях, где точный ответ известен.

### Соглашение о знаке

В коде принято `omega = −J ≤ 0`, где `J` — стоимость. Отсюда названия папок:

| папка | что содержит | в терминах `omega` |
|---|---|---|
| `bounds/upper` | верхние оценки стоимости (значения допустимых стратегий) | нижние оценки `omega` |
| `bounds/lower` | нижние оценки стоимости (релаксации и сертификаты) | верхние оценки `omega` |
| `bounds/convex` | аффинные оценки из выпуклости | внутри всё считается в `J ≥ 0` |

Пакет `bounds/convex` — единственное место, где расчёты идут в стоимости, потому
что выпукла именно `J`; обёртки переводят результат обратно в `omega`.

### Контрольные точки

| состояние | точное значение |
|---|---|
| коллинеарные `x ∥ y` | `omega_1D(X, Y)` — одномерная задача Фуллера |
| самоподобная орбита | `J = λ⁵ / 540`, где `λ = √6 · ‖y‖` |

### Базовые методы и улучшения

* **Базовые** (исходная постановка — оптимизация поворота прямоугольников):
  `bounds/upper/rectangle.py`, `bounds/lower/square.py`.
* **Улучшения**, добавленные в ходе работы: `policy_improvement`, `time_optimal`,
  `convex_hull`, `self_similar` (сверху), `affine_cuts`, `hjb_certificate`
  (снизу).

## `utils/` — инфраструктура

* **`constants.py`** — `Constants`: `BETA ≈ 0.4446` (корень `36β⁴ + 3β² − 2 = 0`,
  задаёт кривую переключения одномерной задачи), `GAMMA ≈ 0.06753`, константы
  золотого сечения, `EPS`, `SQRT5`.
* **`utils.py`** — `OptimizationUtils`: `rotate_vectors`, `grid_search`,
  `golden_section_search`, `two_stage_optimization` (сетка + локальное
  уточнение). Используется везде, где надо оптимизировать угол поворота или
  параметр формы.
* **`geometry.py`** — выпуклые тела и инварианты: `Disc`, `Polygon`
  (`support`, `argmax`, конструкторы вписанных и описанных фигур), `gramian`, а
  также `to_pq` / `from_pq` — инварианты Фуллера `p = ‖x‖²/‖y‖⁴`,
  `q = ⟨x,y⟩/‖y‖³` (область `p ≥ q²`), сводящие задачу к двум параметрам.
* **`reduced.py`** — приведённое описание задачи:
  * `reduced_rates(x, y, u)` — динамика инвариантов при разложении управления
    `u = a·e_y + b·e_⊥`: `ṗ = (2q − 4pa)/n`, `q̇ = (1 − 2qa + √(p−q²)·b)/n`,
    `ṅ = a`;
  * `hjb_residual(p, q, f, f_p, f_q)` — невязка приведённого уравнения
    Гамильтона–Якоби–Беллмана для `omega = ‖y‖⁵ f(p, q)`: ноль для истинной
    функции, `≤ 0` для субрешений;
  * `P_SELF_SIMILAR`, `Q_SELF_SIMILAR` — инварианты самоподобной орбиты
    `(2/3, −2√6/9)`, являющейся равновесием приведённой динамики.
* **`hjb.py`** — `HJBSubsolutionLP`: поиск сертификата-субрешения линейным
  программированием на сетке в `(p, q)`. `build_lp` собирает ограничения
  (максимум по диску заменён максимумом по конечному набору направлений,
  производные противопотоковые), `solve` решает ЛП с боксами
  `f_rect ≤ f ≤ f_square` и штрафуемой переменной запаса, `verify` выполняет
  апостериорную проверку центральными разностями.

## `bounds/common.py`

* `pure_bellman_1d(x, y)` — точная функция Беллмана одномерной задачи Фуллера
  (замкнутая формула через `BETA`, `GAMMA`);
* `scaled_bellman_1d(x, y, a)` — то же для управления в `[−a, a]`;
* `degenerate_case(x, y)` — единая обработка вырождений (нулевое состояние,
  `x = 0`, коллинеарные `x ∥ y`): возвращает точное значение либо `None`.

## `bounds/upper/` — верхние оценки стоимости

Общая идея: любая допустимая стратегия даёт верхнюю оценку стоимости.

* **`rectangle.py`** — `UpperBoundBellmanFunction`. **Базовый метод.** Управление
  ограничивается вписанным прямоугольником со сторонами `(cos ξ, sin ξ)`,
  повёрнутым на угол `φ`. Для прямоугольника задача распадается на две
  одномерные (`‖x‖²` аддитивна, прямоугольник — произведение отрезков), поэтому
  значение выписывается в замкнутом виде; оптимизация двумерная — по `φ` и `ξ`.
* **`policy_improvement.py`** — `PolicyImprovementBound`. Шаг оператора Беллмана
  над уже имеющейся оценкой: `T_h[W](z) = max_u [ W(z_h(u)) − ∫₀^h ‖x‖²/2 dt ]`.
  Выполняется `W ≤ T_h[W] ≤ omega`, то есть результат гарантированно не хуже
  старта; максимум берётся ещё и по нескольким шагам `h`, каждый из которых —
  своя допустимая стратегия. Интеграл стоимости на шаге считается точно.
* **`time_optimal.py`** — `TimeOptimalBound`. Реализация идеи из статьи
  Chikake–Hildebrand: аналитически решается задача **быстродействия** с тем же
  множеством допустимых траекторий, и её траектория подставляется в исходный
  функционал. `_gram_terms` — формулы грамиана через `(τ, τ̄)`, `_fit_params` —
  обращение зависимости по инвариантам `(p, q)` методом Ньютона, `_objective` —
  интегрирование стоимости.
* **`self_similar.py`** — `SelfSimilarControlBound`. Значение функционала на
  точной самоподобной траектории: управление
  `u = exp(i(σ√5·log(T−t) + c))` интегрируется назад от начала координат.
  По сути **валидатор**: орбита занимает одну точку приведённого пространства,
  вне её метод возвращает `−inf`, а на ней обязан дать ровно `−λ⁵/540`.
* **`convex_hull.py`** — `ConvexHullBound`. Верхняя оценка через выпуклую
  комбинацию состояний с известной стоимостью (неравенство Йенсена); обёртка над
  `bounds/convex/jensen.py`. Комбинируется с `rectangle`, поэтому никогда не хуже
  базового метода, и точна на самоподобной орбите.

## `bounds/lower/` — нижние оценки стоимости

Общая идея: заменить круг **бо́льшим** множеством управлений либо предъявить
сертификат — и то, и другое даёт стоимость не больше исходной.

* **`square.py`** — `LowerBoundBellmanFunction`. **Базовый метод.** Круг
  заменяется описанным единичным квадратом, повёрнутым на угол `φ`; задача снова
  распадается на две одномерные, оптимизация идёт только по `φ`. Единичный
  квадрат — единственный минимальный по включению прямоугольник, содержащий круг,
  поэтому в классе прямоугольников эта оценка неулучшаема.
* **`affine_cuts.py`** — `AffineCutsBound`. Нижняя оценка через опорные
  гиперплоскости: в точках, где известны и значение, и градиент стоимости,
  строится касательная `l(z) = J(z₀) + ⟨∇J(z₀), z − z₀⟩`, которая в силу
  выпуклости `J` корректна глобально; берётся максимум по семейству отсечений.
  Обёртка над `bounds/convex/affine.py`, комбинируется с `square`.
* **`hjb_certificate.py`** — `HJBCertificateBound`. Сертификация через
  HJB-неравенство: `fit()` решает ЛП из `utils/hjb.py` и проверяет решение,
  `lower_bound_hjb(x, y)` возвращает сертификат только если он прошёл
  апостериорную проверку, иначе — значение `square`. Тем самым метод никогда не
  выдаёт неподтверждённую оценку.

## `bounds/convex/` — аффинные оценки из выпуклости

Опирается на выпуклость стоимости `J` (динамика линейна, множество управлений и
интегрант выпуклы), поэтому внутри пакета всё считается в `J ≥ 0`. Подробный
разбор — в `bounds/convex/README.md`.

* **`samples.py`** — состояния с точно известной стоимостью: `cost_1d`,
  `grad_cost_1d` (значение и аналитический градиент одномерной задачи);
  `collinear_sample`, `collinear_samples` — коллинеарные состояния вместе с
  **точным градиентом** (поперечные компоненты сопряжённых переменных равны
  нулю); `self_similar_base`, `self_similar_samples` — самоподобная орбита
  (только значения) с масштабом и поворотом под запрос; `exact_cost_if_known(z)`
  — распознавание известных состояний.
* **`affine.py`** — отсечения: `AffineFunction` (`l(z) = ⟨g, z⟩ + c` с флагом
  сертифицированности), `cut_from_sample` и `cut_at_collinear` (опорная
  гиперплоскость), `best_collinear_cut` (подбор точки касания под запрос),
  `compute_lower_affine` (касательные при заданных градиентах либо ЛП по
  коэффициентам), `AffineCutLowerBound` (максимум по отсечениям), `verify_cuts`
  (проверка, что ни одно отсечение не превышает независимую верхнюю оценку).
* **`jensen.py`** — выпуклая оболочка: `build_dictionary(z)` (словарь атомов под
  запрос), `compute_upper_affine` (ЛП `min Σθᵢ Jᵢ` при `Σθᵢ zᵢ = z`, `Σθᵢ = 1`;
  возвращает значение, веса и двойственную аффинную функцию),
  `JensenUpperBound`.

Полезное следствие двойственности: аффинная функция, ограниченная только в
точках выборки и максимизируемая в запросе, по двойственности ЛП даёт
**верхнюю** оценку (Йенсена), а не нижнюю. Нижней она становится лишь при
ограничении на всей области — что бесплатно обеспечивают касательные с точным
градиентом.

## `tests/` — эталонные тесты

* **`test_benchmarks.py`** — коллинеарный случай воспроизводит `omega_1D` для
  обеих оценок; обе границы зажимают точное `−1/540`; `time_optimal`
  воспроизводит значения из статьи; `self_similar` даёт точное значение с
  правильным знаком; приведённая динамика совпадает с конечными разностями;
  самоподобная точка оказывается равновесием с `a² + b² = 1`; policy improvement
  валиден и не хуже старта.
* **`test_convex_bounds.py`** — аналитический градиент, выпуклость `J`,
  распознавание точных значений, касание отсечений и их неперевышение верхней
  оценки, точность Йенсена на орбите, ЛП-двойственность.

Запуск: `python -m pytest tests -q`.

## `plot_bounds.py` — графики

Скрипт сравнения всех методов; отсутствующие модули пропускаются, результаты
кэшируются в `figures/cache_*.json`.

```
python plot_bounds.py            # рис. 1 и 2
python plot_bounds.py --grid     # + карта по приведённому пространству
```

* **Рис. 1** — срез `q = −2√6/9`, `‖y‖ = 1`, проходящий через самоподобную
  орбиту: все оценки в абсолютных величинах и в нормировке
  «0 — квадрат, 1 — прямоугольник».
* **Рис. 2** — отклонение каждого метода от точного значения в самоподобной точке.
* **Рис. 3** (по флагу) — ширина коридора «было / стало» по `(r, φ)` и карта
  того, какой метод даёт верхнюю оценку в каждой точке.

## Текущие результаты

Самоподобная точка, точное значение `J = λ⁵ / 540`:

| метод | отклонение | сторона |
|---|---|---|
| аффинные отсечения | 25.62 % | снизу |
| квадрат (базовый) | 11.19 % | снизу |
| быстродействие | 6.81 % | сверху |
| прямоугольник (базовый) | 3.26 % | сверху |
| policy improvement | 2.22 % | сверху |
| выпуклая оболочка (Йенсен) | 0.00 % | сверху |

Сверху коридор поджат: policy improvement выигрывает у прямоугольника
равномерно, выпуклая оболочка делает верхнюю оценку точной на самоподобной
орбите. Снизу базовый квадрат пока не превзойдён — он сам является выпуклой
нижней оценкой, а касательные доступны только на коллинеарном множестве, где
квадрат и так точен. Дальнейшее улучшение упирается в поперечные компоненты
сопряжённых переменных на самоподобной орбите: они не определяются известными
соотношениями и остаются открытым вопросом.
